# Deep reverse procedure

Use this mode when the user asks for complete/full reverse engineering, JSC bytecode, native-module internals, or the highest-fidelity archive obtainable from the installed release.

If the request also asks for compilable `.node` source or runnable replacements, complete this static procedure first, then read [native-reconstruction.md](native-reconstruction.md). Static evidence remains canonical even after compatible source is added.

## Inputs

- Canonical snapshot repository with `extracted/cli.js`, all packed `.node` files, and `analysis/unpack-manifest.json`.
- Raw JSC bytecode dumped from the manifest's exact `offsetInFile` and `length`.
- A readable JavaScript view produced from `extracted/cli.js` by a pinned parser/formatter such as esbuild.
- macOS tools: `file`, `lipo`, `otool`, `nm`, `strings`, `codesign`, `dwarfdump`, `xcrun swift-demangle`.

## Build

```bash
python3 skill/claude-code-version-diff/scripts/build_deep_reverse.py \
  REPO \
  --bytecode RAW_CLI_JSC \
  --readable-js READABLE_CLI_JS \
  --esbuild-version ESBUILD_VERSION
```

The script rebuilds `reverse/` deterministically. Preserve the raw bytecode input outside Git; `reverse/bytecode/cli.jsc.gz` is the committed lossless form.

## Required evidence

- Bytecode: exact executable offset, uncompressed size/hash, deterministic gzip size/hash, and compressed full strings.
- JavaScript: canonical/readable hashes, generator version, line count, and stable environment/host inventory equality.
- Native modules: source hash, architecture list, file/UUID/signature records, per-architecture headers/load commands/dylibs/imports/exports/symbols/Objective-C data/Swift symbols/disassembly, and full strings.
- Cross-version indexes: stable identifiers, hosts, URLs, probable dotted config keys, build paths, native architectures/dependencies/imports/exports/N-API imports/project Swift symbols.

## Validation

```bash
python3 skill/claude-code-version-diff/scripts/validate_deep_reverse.py REPO
python3 skill/claude-code-version-diff/scripts/validate_snapshot.py REPO
```

Re-hash the installed executable after the build. Verify the decompressed JSC hash, readable-JavaScript parse, Git maximum file size, branch name, and remote commit.

## Interpretation

Treat stable names and behavior as stronger evidence than offsets or raw disassembly churn. A changed JSC hash proves generated bytecode changed, not which feature changed. A new native import or demangled project symbol is useful implementation evidence, but connect it to user-facing behavior only when the bundle, CLI surface, or release notes corroborate it.
